Is your Lovable app secure? A plain English checklist

By Taimoor Ahmed · 5 min read

Lovable makes it remarkably easy to build an app with user accounts and a database. That's also why security problems slip through. The app looks finished and works in the demo, but the data behind it may be open to anyone who knows where to look.

Most Lovable apps use Supabase for the database and logins. Here's a plain English checklist to work through before you put real customers or real data on it.

1. Turn on row level security for every table

Row level security (RLS) is the rule that decides who can see which rows in your database. Without it, any logged in user, and sometimes anyone at all, can read every record. Open Supabase, check every table, and make sure RLS is on with a policy that only lets people see their own data.

Quick test: create two test accounts. Log in as one and try to view or edit the other's records. If you can, so can your customers.

2. Know which key is which

Supabase gives you a public key and a secret service key. The public key is meant to be in the browser and is only safe when RLS is set up properly. The service key must never appear in your front end code, because it skips every security rule. Search your project for it.

3. Keep other secrets on the server

Keys for OpenAI, Stripe, email services and similar should live in server side functions, not in the code that runs in the browser. If a prompt asked the AI to "just call the API", check where it put the key.

4. Check every page and action, not just the login screen

Hiding an admin button doesn't stop someone calling the action behind it. Make sure the database rules and server functions check who the user is and what role they have, every time.

5. Lock down file storage

If users upload documents or photos, check your storage buckets. Public buckets mean anyone with the link can see the file. Anything personal, like IDs, invoices or medical documents, should be private.

6. Tighten up sign up and passwords

Turn on email confirmation, set sensible password rules and decide who is actually allowed to sign up. If it's an internal tool, don't leave public sign up open.

7. Limit abuse

Forms and AI features can be hammered by bots, which can run up big bills. Add rate limits or a simple bot check on public forms and anything that calls a paid API.

8. Back it up and watch it

Set up regular backups and test a restore. Add error tracking so you know when something breaks. If you handle personal information, remember Australian privacy law expects you to protect it and to act if there's a breach.
