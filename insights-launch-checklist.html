Launching an AI built app

7 things to fix before you launch your Lovable or Bolt app

By Taimoor Ahmed · 5 min read

AI tools like Lovable, Bolt, Cursor and Replit have made it possible to build a working app in a weekend. That's genuinely exciting. But most of the apps we review have the same handful of problems hiding under a nice looking interface. None of them show up in a demo. All of them show up once real customers arrive.

Here are the seven we see most, and what to do about each one.

1. Secret keys sitting in the browser

AI tools often put API keys straight into the front end so things work quickly. Anyone who opens the browser tools can copy them and run up your bill or read your data. Move every secret key to the server and call it from there.

2. Anyone can read anyone's data

If you use Supabase or Firebase, check your database rules. A surprising number of apps let any logged in user read every other user's records. Turn on row level security and test it with two accounts.

3. Logins that are easy to get around

Check that every page and every API call actually checks who the user is, not just the ones with a login screen in front of them. Hiding a button is not the same as blocking access.

4. No backups

Ask yourself: if the database was wiped tonight, what would you lose? Set up automatic daily backups and try restoring one before you need it.

5. You only find out about errors from customers

Add error tracking such as Sentry so you hear about crashes first. It takes an hour to set up and saves a lot of awkward emails.

6. Hosting on a free preview link

Preview links are fine for testing, not for customers. Put the app on your own domain, on hosting you control, with your own accounts. If the builder tool changes its plans tomorrow, your app should keep running.

7. Nobody can explain how it works

AI generated code can grow fast and messy. Before launch, make sure there is a short write up of how the app fits together, where it is hosted and how to deploy it. Future you, or your next developer, will be grateful.
